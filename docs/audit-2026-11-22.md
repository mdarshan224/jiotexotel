# Junk It Out audit and remediation — 22 November 2026

## Confirmed defects fixed

- Booking and wallet pages read the wrong wallet response shape, making valid balances appear unavailable. Both now use the authenticated wallet response and show spendable funds, excluding expired bonus points.
- Wallet-selected bookings eagerly created online gateway orders. Booking now preserves the chosen method, wallet retries use the wallet endpoint, and online retries ignore pending wallet records.
- A late online capture could conflict with a wallet debit if a gateway attempt was overwritten. Wallet payment now rejects an already-created or unresolved online attempt with explicit recovery guidance. It does not silently switch a live gateway order to wallet.
- Wallet-paid orders used a status that the dispatch and cancellation refund paths did not recognize. They now use CAPTURED and trigger the existing idempotent dispatcher after settlement.
- Subscription purchases and plan changes updated only the rupee balance. All wallet-funded subscription actions now use the same paise, paid-funds, bonus-grant and allocation ledger as booking payments, atomically.
- Subscription wallet purchases, renewals and changes have customer-scoped persisted attempt identifiers. Lost-response retries return the existing pass; failed transactions roll back the pass, payment, and debit. The mobile/browser client retains pending attempt IDs across reloads.
- A queued plan change could overlap an already queued pass. Wallet plan changes start after the latest active pass expiry.
- Exhausted passes hid later eligible passes. Entitlement lookup now selects the earliest usable pass. A configured zero pickup limit retains unlimited semantics.
- Fully covered pickups had no payment callback to dispatch them. The booking route captures their zero-value order and invokes dispatch without a charge.
- Cancelling a subscription pickup failed to release the reserved entitlement. The cancellation transaction returns it once; covered zero-value orders do not create monetary refund requests.
- Approved wallet refunds incorrectly went through the external gateway. They now return funds to the original paid/bonus buckets, retain original bonus expiry, and deduplicate credits.
- Checkout dismissal and verification errors could leave wallet actions locked. Mutual action locks, cleanup and surfaced errors now prevent overlapping actions and permit retry after dismissal.
- A stale bonus quote could survive an amount change or raise an unhandled network error. Quotes now discard stale responses and handle failures.
- Booking clears stale balances/passes on logout or refresh failure; retry requires customer sign-in. Mobile confirmation labels distinguish wallet and online payment and preserve the fixed bottom action flow.
- Worker logs showed hung requests. Prisma engines and in-flight booking/gateway promises are now isolated per request; bootstrap and SQLite module caches no longer share pending I/O promises across requests.

## Scope and remaining verification limits

No live payments, refunds, SMS sends or customer record edits were used for QA. Existing live credentials, domain, public audience and database schema are preserved. This release does not invoke account-deletion maintenance or alter schedules.

Automatic approval review rejected a broad legacy test run because an AI support test attempted an external OpenAI request with unverified data. It was not rerun. The final offline suite uses an explicit reviewed allowlist and rejects unexpected fetches; the AI support provider path is not certified by this audit. Several legacy tests are standalone Node assertion scripts or require PostgreSQL, rather than usable Vitest suites against this D1 deployment.

Physical Android/iOS app builds, installed UPI application discovery, bank authorization, live gateway capture/webhooks, push delivery, native permission handling and App Store review were not exercised on devices. Browser and unit checks cannot certify those external paths. The existing Android UPI configuration is preserved and covered by option tests.

The existing AtomicD1 adapter snapshots the database for interactive transactions, with row/size limits. It remains suitable only while data fits those bounds; this audit preserves its fail-closed concurrency guards rather than replacing the storage architecture. Request isolation addresses the identified cross-request I/O problem; post-deploy logs and real traffic remain necessary to measure its production effect.
